# Клиент: правила списка, пилюль, обновления и спидтеста

Единая спецификация. Любая правка этих зон проверяется против **всех** пунктов, а не против одного
бага. Источник истины для реализующего агента; расхождение кода и этого файла — дефект.

## 1. Строки списка

1. **v2-подписка**: одна строка на пул (`<shard>:<pool>`), протоколы пула — пилюлями в этой строке.
2. **v1 (старая) подписка**: одна строка на протокол; `AmneziaWG` и `AmneziaWG Mobile` — **обе**
   строки, мобильная выше, у каждой свой `connection_uuid`.
3. **Дубли недопустимы**: строка пула и legacy-строка того же протокола той же подписки одновременно
   не рисуются. Legacy-строка показывается только если её протокола нет ни в одном пуле подписки.
4. Если у подписки исчезли пулы (нет гранта) — её legacy-строки снова видны (скрытие не кэшируется).

## 2. Пилюли протоколов

1. Пилюли видны только если пул отдаёт больше одного протокола; у однопротокольного пула — строкой-подписью.
2. Выбранная пилюля определяет: подпись строки, карточку коннекта, `displayInfo.kind`/`proto` строки.
3. Переключение пилюли **не** теряет `kind`: `hysteria2` остаётся `client_config`, пиры — `peer`.
4. Пилюля не влияет на другие строки и не меняет порядок строк в списке.

## 3. Обновление подписки

1. Ответ с пулами → строки этой подписки **заменяются** (не сливаются) — это защита от дублей.
2. Ответ **без пулов** (нет гранта) или ошибка/таймаут запроса → строки, кэш конфигов и выбор сервера
   **остаются как были**; никакого «список опустел».
3. Для `client_config`-карточки считается отпечаток payload (server/port/sni/auth/obfs). Изменился →
   кэшированный конфиг выбрасывается, коннект собирает новый локально (без api).
4. Параметры одного и того же протокола (obfs/auth/sni/port) меняются обновлением, **без** удаления
   и повторного добавления подписки.

## 4. Коннект

1. `kind = client_config` → конфиг строится из payload, `POST /v1/peers` не вызывается, пир не тратится.
2. `kind = peer` → `POST /v1/peers`, кэш переиспользуется (лимит пиров не жжём).
3. В лог пишется выбранный путь: `[PEERS] client_config tunnel: <card>` либо `[PEERS] create peer for <card>`.

## 5. Спидтест

1. Тестируется **только выбранная в списке подписка**; «Все» — все подписки аккаунта.
2. Пуловая строка даёт по одному target на endpoint **активного** протокола; выключенные юзером
   адреса пропускаются.
3. Legacy-строки, скрытые пулом, не тестируются.
4. Строки без bench-эндпоинта пропускаются, и каждая причина пропуска пишется в лог.
5. Подпись подписки в результатах — когда фильтр «Все».

## 6. Проверка перед сборкой

Харнесс на реальных файлах (`peerConfigBuilder.cpp`, `apiUtils.cpp`, функции QML, `serverTestController`)
прогоняет минимум эти случаи: v2-пул с двумя протоколами; v1 с обеими Amnezia; refresh с пулами;
refresh без пулов; ошибка запроса; смена obfs/auth/sni/port в payload; спидтест по v1- и v2-подписке.
Без зелёного прогона по всем пунктам сборка не выпускается.
