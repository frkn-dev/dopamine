# Мессенджер «последней мили» в Dopamine — рисерч

Идея: встроить в VPN-приложение простой мессенджер, который работает, когда
всё остальное не работает. Не конкурент Telegram/WhatsApp — запасной канал
связи («написать маме, что долетела»). В идеале — mesh без интернета.

## Моя оценка идеи

Ниша реальная и доказанная цифрами: BitChat (Jack Dorsey, BLE mesh, июль 2025)
собрал 438k скачиваний за неделю блэкаута в Иране, всплески в Непале,
Мадагаскаре. Спрос на «связь, когда всё выключили» — не гипотеза, а факт.

Важная честная оговорка про ценность: **пока есть хоть какой-то интернет и
наш туннель жив — любой мессенджер уже работает через Dopamine** (туннель
системный). Поэтому уникальная ценность встроенного мессенджера — ровно два
сценария:

1. **интернета нет вообще** (шатдаун) → нужен mesh (BLE/Wi-Fi Direct);
2. туннель не поднимается, но какой-то транспорт жив → сообщение можно
   прокинуть через наши же серверы (почти бесплатно, у нас уже есть канал).

Сценарий 2 даётся дёшево, сценарий 1 — это 80% ценности и 80% сложности.

## Жёсткие платформенные ограничения

### iOS (главные грабли)
- **Фон почти мёртв**: BLE-реклама в фоне урезана (payload выкидывается,
  сканирование троттлится), нужны background modes `bluetooth-central/peripheral`
  и обоснование в App Review. Реально работает паттерн «приложение открыто»
  — для протестов/шатдаунов это приемлемо (так живут Bridgefy и BitChat).
- **Multipeer Connectivity** (Apple-native mesh) — только iOS↔iOS, с Android
  несовместим.
- Range: BLE ~10–30 м, AWDL (Wi-Fi p2p) ~50–100 м.

### Android
- BLE + Nearby Connections — полноценнее, фон лучше (foreground service).
- Свой BLE-стек проще, но cross-platform протокол с iOS надо делать самим.

### Вывод по платформам
Кросс-платформенный mesh = свой BLE GATT протокол на обеих ОС. С нуля это
месяцы на надёжность (фрагментация, MTU, переподключения, батарея).

## Существующие решения (что можно взять)

| Решение | Лицензия | Статус | Годность для нас |
|---|---|---|---|
| **BitChat** ([iOS](https://github.com/permissionlesstech/bitchat), [Android](https://github.com/permissionlesstech/bitchat-android)) | **Unlicense (public domain)** | Активный, iOS+Android протокол-совместимы, BLE mesh до 7 хопов, Noise E2E, без аккаунтов | **Лучший кандидат.** Можно забрать mesh-ядро целиком |
| Bridgefy SDK | коммерч. | Живой, но отзывы: логин онлайн (!), ненадёжная доставка | Не подходит по модели (онлайн-логин убивает смысл) |
| Berty | OSS | BLE+IPFS, не аудирован, тяжёлый (IPFS), проект почти заморожен | Тяжело и сыро |
| Briar | GPL | Android-only, Tor/BT/Wi-Fi sync | Нет iOS — мимо |
| Meshtastic | GPL | LoRa-железки | Не телефоны |
| Multipeer + Nearby самим | — | — | Несовместимы между ОС → не вариант |

### BitChat — детали
- Архитектура: BLE mesh (офлайн) + Nostr (онлайн). Нам нужна только mesh-часть.
- Крипто: Noise Protocol Framework, эфемерные ID с ротацией, cover traffic.
- **Риск 1**: исследователи нашли критические уязвимости (критикуют как
  «vibe coding») — брать ядро можно, но нужен свой аудит крипто/протокола.
- **Риск 2**: Индия уже потребовала от GitHub takedown репозиториев BitChat
  (июль 2026) — регуляторный жар на эту тему есть и будет.

## Предлагаемая архитектура (если делаем)

Фаза 1 — MVP «mesh-записка» (3–6 недель, 1 разработчик):
- Берём BitChat mesh-ядро (iOS Swift / Android Kotlin, Unlicense).
- Свой UI в Qt/QML (экран чата), мост по образцу IosController/AndroidController.
- Только текст, только foreground, публичный канал + 1:1 по отпечатку ключа.
- Без аккаунтов: ключевая пара на устройстве, обмен контактами — QR.

Фаза 2 — надёжность (1–2 мес):
- Store-and-forward (эпидемическая маршрутизация как у Briar/BitChat TTL-хопы).
- Батарея, переподключения, фрагментация, аудит крипто.
- Фон насколько позволят iOS background modes.

Фаза 3 — гибрид с нашим бэком (опционально):
- Когда интернет есть — доставка через наши серверы (очередь офлайн-сообщений).
- Это дешевле mesh и закрывает сценарий «мама в другом городе».

## Чего НЕ делать

- Не писать свой mesh-протокол с нуля (4–6+ мес и хуже).
- Не тащить IPFS/Berty — тяжело и мёртво.
- Не обещать E2E-безопасность без аудита — аудитория FRKN чувствительная,
  один CVE в мессенджере бьёт по всему бренду.
- Не ждать, что mesh спасёт без плотности: mesh работает, когда рядом много
  устройств с приложением. Для FRKN это протесты/толпы/аэропорты — там ок.

## Риски App Store / регуляторика

- BLE background modes в Review надо обосновать (прецеденты есть — Bridgefy,
  BitChat в сторе).
- VPN + анонимный mesh-мессенджер в одном приложении — повышенное внимание
  регуляторов (см. тейкдаун BitChat в Индии). К 4.3(a) нашей текущей заявки
  это отношения не имеет, но в РФ/др. юрисдикциях может добавить шума.

## Оценка трудозатрат (честно)

| Вариант | Срок |
|---|---|
| MVP на ядре BitChat, текст, foreground | 3–6 недель |
| Production (фон, батарея, аудит) | 2–4 месяца |
| Свой протокол с нуля | 4–6+ месяцев, не надо |

## Рекомендация

Делать MVP на ядре BitChat в отдельной ветке, спрятать за фиче-флаг, катнуть
тестерам. Если метрики/фидбек живые — вкладываться в фазу 2. Это самый дешёвый
способ проверить нишу, не утаскивая основную разработку VPN.
