# Server availability & latency — research

Цель: в списке серверов показывать доступность и пинг («32 ms» / «offline»).
Наши транспорты: VLESS TCP Reality, VLESS gRPC Reality, VLESS XHTTP (CDN),
Hysteria2 (QUIC/UDP), AmneziaWG (UDP), WireGuard (UDP).

## Принципиальные ограничения (iOS)

- **Проба из приложения при активном VPN** пойдёт через туннель (системные
  маршруты), т.е. измерим «доступность через текущий сервер», а не напрямую.
  Привязать сокет к конкретному интерфейсу на iOS нельзя. Вывод: замеры
  делаем только когда не подключены (или явно помечаем «измерено через VPN»).
- **ICMP ping** на iOS возможен (SimplePing, datagram ICMP, без entitlement),
  но многие хосты режут ICMP → ложные «offline». Только как вспомогательный
  сигнал.
- **UDP по дизайну молчит** (WG/AWG не отвечают на мусор) — «нет ответа»
  ничего не значит; нужен валидный handshake.

## Матрица методов по протоколам

| Протокол | Дешёвая проверка | Точная проверка | Стоимость точной |
|---|---|---|---|
| VLESS TCP Reality | TCP connect + RTT (QTcpSocket) | TLS ClientHello(SNI) → ждём ServerHello | низкая |
| VLESS gRPC Reality | TCP connect + RTT | то же | низкая |
| VLESS XHTTP / CDN | TCP connect + RTT (443) | то же | низкая |
| Hysteria2 (QUIC/UDP) | ICMP (слабо) / ничего | QUIC Initial → handshake response | высокая |
| AmneziaWG | ICMP (слабо) / ничего | WG handshake initiation → response | средняя |
| WireGuard | ICMP (слабо) / ничего | WG handshake initiation → response | средняя |

Заметки:

- **TCP connect** (SYN→SYN/ACK) даёт reachability+RTT за ~50–300 мс на сервер.
  Не доказывает, что Reality-жест пройдёт (файрвол может принимать TCP), но
  хороший прокси-сигнал. QTcpSocket работает на iOS без ограничений.
- **TLS-проба** для Reality: шлём ClientHello с SNI ноды и ждём ServerHello —
  отсекает DPI-«гасит TLS», точнее чем просто порт. Реализуемо через
  QSslSocket (начать handshake, засечь время до encrypted(), ошибиться и выйти).
- **WG/AWG handshake**: у нас в конфиге уже есть ключи → валидный initiation.
  Реализация Noise IK вручную — крипто-работа. Проще: добавить в нашу Go-либу
  (WireGuardKitGo) экспортируемую функцию-пробу
  `wgHandshakeRTT(endpoint, serverPubKey, psk) → rtt|error` (вся криптография
  там уже есть, wireguard-go умеет handshake). Пересборка либы + вызов из
  Swift/C++ — средняя сложность, самый честный метод для UDP.
- **Hysteria2**: руками QUIC Initial — тяжело (дни). Практичнее проб-harness
  на встроенном libxray: поднять временный outbound и засечь handshake —
  средне-тяжело, но ядро уже внутри NE.

## Рекомендуемая архитектура (по фазам)

**Фаза 1 — MVP (1–2 дня), закрывает большинство:**
- TCP-проба для всех TCP-серверов (VLESS всех видов): QTcpSocket, timeout
  2с, параллельно ~8, замер RTT.
- Для UDP-серверов: ICMP ping как вспомогательный; если ICMP закрыт —
  показываем «n/a» вместо «offline» (не врём юзеру).
- UI: бейдж в строке сервера справа (мс, цвет: зелёный < 120, жёлтый < 300,
  серый «n/a», красный «offline»).
- Триггер: при открытии списка серверов, троттлинг 30с, только когда не
  подключены. Кэш на сессию + последний результат персистентно.

**Фаза 2 — точный UDP (WG/AWG):**
- Go-проба handshake в WireGuardKitGo (экспорт `wgHandshakeRTT`),
  пересборка либы, вызов из клиента. 1–2 дня.

**Фаза 3 — точный H2 + ground truth:**
- H2 handshake-проба через libxray harness.
- Записываем факты реальных подключений (успех/время хендшейка) и используем
  для бейджей «работал 2ч назад» — самые честные данные, бесплатно.

## UX-детали

- Бейдж обновляется фоново, список не дёргается (позиции серверов не меняем
  на лету — сортировка по пингу только по явной кнопке, если вообще нужна).
- «offline» показываем только при уверенном отказе (TCP refused/timeout 2–3
  попытки), не при «нет ответа на UDP/ICMP».
- Сеть проб: системная, короткие таймауты, отмена при закрытии шторки.

## Что НЕ делаем (антипаттерны)

- Не пингуем всё подряд постоянно в фоне — батарея/трафик.
- Не считаем «нет ICMP-ответа» за «сервер мёртв».
- Не меряем при активном VPN без оговорки — метрика будет лживой.
