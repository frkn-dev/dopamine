# Контракт для клиента: `speedtest_url`

Как приложению (Dopamine) мерить скорость до нод. Дополняет ТЗ
`api-speedtest-url.md`; здесь — только то, что нужно потребителю.

Статус: api **0.6.134+** отдаёт поле в `/status`, **0.6.135+** — ещё в
`/v1/services` и `/v1/config`. Если поля нет — это старый api или нода без бенча:
вести себя как «нет бенча» (п. 5), а не строить имя самостоятельно.

---

## 1. Откуда брать

```http
GET https://api.frkn.org/status
```

Публичный, без ключа. В `response[]` у каждой ноды пула:

```json
{
  "hostname": "at.frkn.org",
  "address": "177.177.20.172",
  "label": "AT AWG EU-09",
  "status": "Online",
  "ports": [443],
  "pool": "EU Рилзопровод",
  "speedtest_url": "https://mis-at-vie-bench-01.bench.beacon.frkn.org:19443"
}
```

То же значение приходит в объекте коннекшена:

```jsonc
// POST /v1/services -> GatewayServicesResponse.connections[]
{
  "connection_uuid": "1ac65b82-…",
  "node_id": "7f3c9a01-…",
  "node_ips": ["177.177.20.172"],
  "node_ports": { "177.177.20.172": 443 },
  "pool": "EU Рилзопровод",
  "speedtest_url": "https://mis-at-vie-bench-01.bench.beacon.frkn.org:19443"
}
```

и в ответе `POST /v1/config` (рядом с `node_ips`/`node_ports`). Если клиенту нужен
адрес вместе с коннектом — брать оттуда, отдельный запрос `/status` не нужен.
Где именно читать — `/v1/services[…]` (список серверов) или `/status` (общий
список нод): значение одно и то же.

## 2. Что это за строка

- **Base URL**: схема `https`, хост и **явный порт** (сейчас `19443`).
- **Без пути и без завершающего слэша.** Путь добавляет клиент.
- Один и тот же адрес для всех протоколов одной ноды (`amnezia-awg`,
  `amnezia-wg-mobile`, …) и для всех её `node_ips`.
- Ведёт **на саму ноду**, не на прокси. Через свой сервер не гонять: измерите
  канал сервера, а не путь клиента до ноды.

## 3. Как мерить

Все запросы — на тот же base URL, с `?cb=<random>`, чтобы не поймать кэш
(сервер и сам отдаёт `Cache-Control: no-store`, но прокси по пути бывают упрямы).

| что | запрос | размер | таймаут |
|---|---|---|---|
| пинг | `GET {url}/speedtest/ping.txt?cb=…` | 1 байт | 4–6 с |
| скорость, проба | `GET {url}/speedtest/1mb.test?cb=…` | 1 МиБ | 6 с |
| скорость, основной | `GET {url}/speedtest/10mb.test?cb=…` | 10 МиБ | 12 с |

Рекомендации, проверенные на нашей же странице:

1. **Пинг:** один «прогревающий» запрос (DNS + TCP + TLS), затем 3 замера по
   уже установленному соединению; брать **минимум**. Джиттер = max − min этих
   трёх. Первый запрос без прогрева даёт +200…300 мс и врёт.
2. **Скорость:** сначала 1 МиБ. Если уложились в ~0.9 с — качать 10 МиБ и
   считать по нему (на быстрых каналах 1 МиБ занижает). Считать
   `bytes * 8 / seconds / 1e6` = Мбит/с.
3. **Параллельность:** не больше **3 нод одновременно**. При десятках
   одновременных соединений ОС и TLS-стек ставят запросы в очередь, и замеры
   начинают «не укладываться в таймаут» — это мы наблюдали на веб-странице.
4. **Ноды со `status != "Online"`** не мерить: heartbeat нет, сервер, скорее
   всего, недоступен.
5. Ответы ожидаются `200` с `Content-Length` 1048576 / 10485760. CORS
   `Access-Control-Allow-Origin: *` на этих эндпоинтах уже есть (нужно для
   веба, приложению безразлично).
6. **ETag/If-None-Match не слать**, `Accept-Encoding` — `identity` (файл и так
   несжимаемый, но gzip по пути только съест время).

## 4. Чтение результата

Порог «пользователю понятно» (та же сетка, что на странице и в ТЗ):

| Мбит/с | что это значит |
|---|---|
| ≥ 150 | 8K на нескольких устройствах |
| ≥ 100 | 8K |
| ≥ 80 | 4K на нескольких устройствах |
| ≥ 50 | 4K |
| ≥ 25 | 4K с небольшим запасом |
| ≥ 10 | HD |
| ≥ 5 | HD на грани |
| < 5 | веб и мессенджеры |

Отдельная плашка **gaming** — при пинге ≤ 60 мс: играм нужна задержка, а не
ширина канала.

## 5. `null` — это нормальное состояние

`speedtest_url: null` означает «у этой ноды нет тест-файла» (премиум-слоты,
легаси-ноды). Показывать «нет тест-файла»/«—», **не** «0 Мбит/с» и не ошибку.
Ноль — это измеренная скорость, `null` — отсутствие измерения, это разные вещи
для пользователя.

## 6. Чего нельзя делать

- **Строить адрес из hostname.** Схема `<label>.bench.beacon.frkn.org` мертва
  (NXDOMAIN с 2026-11-14): имена в зоне теперь
  `<hoster>-<cc>-<city>-bench-<nn>.bench.beacon.frkn.org`, и ни провайдер, ни
  город из `eu01`/`at`/`msk-tw` не выводятся. Фолбэка нет — нет поля, значит
  нет замера.
- Кэшировать `speedtest_url` в приложении дольше одного запуска: api может
  переехать на другой хост без изменения версии. Читать при каждом открытии
  экрана «Тест серверов».
- Менять порт «на глаз» (9443/443 — это инбаунды, не бенч).

## 7. Приёмка на своей стороне

```bash
# 1. поле есть у всех пуловых нод
curl -s https://api.frkn.org/status \
| jq -r '.response[] | select(.pool) | "\(.hostname)\t\(.speedtest_url)"'

# 2. каждый адрес живой и отдаёт файл
curl -s https://api.frkn.org/status \
| jq -r '.response[] | select(.pool) | .speedtest_url' \
| while read -r u; do printf '%s ' "$u"; \
  curl -s -o /dev/null -w '%{http_code} %{size_download}\n' "$u/speedtest/1mb.test"; done
```

Ожидаемо: 10 строк (3 пула), у каждой непустой адрес, каждый отвечает
`200 1048576`.
