# Дроп 4.8.14.81 — что изменилось с релиза на сайте (4.8.14.70)

Составлено по рабочему дереву `dev` (≈60 изменённых файлов, ~8 000 строк) —
«дроп» = набор изменений клиента между публикациями. Разделы — по тому, что
чувствует пользователь.

## 1. Подключение: один предсказуемый сценарий

- **Всегда один путь:** `Calculating the best option…` (расчёт, бюджет 3 с) →
  `Connecting` → `Connected`. Быстрый путь на запомненный адрес **выключен**
  (`kUseFastPath = false`): он давал разное поведение в разных случаях.
- **`Connected` = есть трафик.** iOS NE отдаёт `Connected` сразу после старта
  расширения, поэтому состояние подтверждается рукопожатием (`rx>0` или
  `last_handshake`), ожидание — 3 с. Не подтвердилось → адрес считается мёртвым
  и клиент сразу берёт следующий (раньше висело 30–54 с и показывался ложный
  `Connected` без байтов — баг был найден на LTE).
- **Смена карточки на живом туннеле:** сначала гасим старый туннель, затем
  считаем новый. `Disconnecting`/`Reconnecting` во время этой операции не
  показываются — на экране держится `Calculating the best option…`, дальше один
  `Connecting`.
- **Убран `Preparing` с горячего пути**; сторож зависшей подготовки больше не
  рвёт идущий дозвон.
- **Истёкшая подписка** — `Subscription expired` и сообщение про продление,
  вместо «сервер не отвечает».

## 2. Расчёт варианта (алгоритм выбора)

- Для строки с пулом всегда прогоняются пробы: настоящие рукопожатия AWG с
  junk-параметрами I1–I5, по одному за раз (гонка рукопожатий с одним ключом
  отбрасывается сервером).
- **Порт на каждый адрес** (`node_ports`, поддержан и компактный массив);
  при отсутствии карты — порт протокола из контейнера строки.
- **Best-first**: живые адреса по возрастанию RTT, затем адреса без замеров по
  весу. Раньше первый адрес выбирался взвешенным случайным броском — из-за
  этого первая попытка могла уйти в мёртвый адрес и ждать таймаут.
- **Пинг — вето, не множитель**: адрес отбрасывается, если он хуже лучшего на
  150 мс и при этом медленнее 200 мс.
- **Веса (`node_weights`)**: дефолт 100, `0`/минус = «не задан»; вес — второй
  критерий (для адресов без замеров). Прод api уже 0.6.119 → веса реально
  приезжают.
- **Провалившие пробу адреса** идут вторым кругом; **выключенный пользователем
  адрес не используется никогда**.
- Пробы запрещены на поднятом туннеле (результаты через VPN врут и стираются).
- Кэш замеров — 5 минут, сохраняется на диск (`Conf·endpointHealthCache`).

## 3. Выбор сервера запоминается

- Тап по строке сохраняет идентичность выбора (`connection_uuid + node_id`):
  раньше писался только `defaultIndex`, и после перезапуска поднимался
  случайный сервер (FK/EST1).
- Восстановление при обновлении подписки: `uuid+node` → `uuid+pool+protocol` →
  `pool+protocol` → прежний default → прежняя позиция.
- Убрано принудительное `processedIndex = defaultIndex` при старте, которое
  перетирало выбор.

## 4. Карточка сервера

- Вердикты: `unreachable` (проба была и не ответила), `unreachable · cached`,
  `not measured yet`, `not checked — VPN is on`, `checking… · 65 ms last`,
  `65 ms · available / cached / in use`.
- Тумблер адреса гаснет и блокируется при любом отрицательном замере (и свежем,
  и из кэша) — раньше подпись и переключатель расходились.
- Переключение адреса на живом туннеле → тост «applies after you reconnect».
- Исправлены три причины ложного `not measured`: порт контейнера `awg-mobile`,
  поиск health по чужой строке, непересчитывавшийся QML-биндинг после
  сворачивания приложения (добавлен `endpointHealthRevision`).

## 5. Туннель: контроль живости

- Пробы сквозь туннель каждые 3 с; 9 провалов подряд (~30 с) → туннель мёртв.
- `Keep reconnecting` включён → `Reconnecting…` и автоперезапуск (тот же адрес,
  затем следующий), не больше 3 перезапусков за 10 минут.
- Выключен → честное `Connected — no internet`, без бесконечных циклов.
- Сторож ручной попытки больше не срабатывает, когда туннель уже `Connected`
  (раньше он рвал живой туннель на ожидании рукопожатия — те самые лишние
  секунды при смене пула).

## 6. Стабильность

- **Крэш при коннекте** (`SIGSEGV` в `objc_msgSend` из блока
  `IosController::connectVpn`): обёртка хранилась как `void*` и не удерживалась
  ARC — исправлено `__bridge_retained`.
- `IOSController::connectVpn` больше не мессенджит освобождённые объекты.
- Убрана временная диагностика, которая на каждый дозвон синхронно писала
  настройки на диск (нагрузка на cfprefsd во время коннекта).

## 7. Телеметрия и поддержка

- Отчёты v2: `device` (модель, RAM, локаль, и на iOS/macOS),
  `network.ipv6_available`, `disk_free_mb`, `settings {…}`,
  `probe.handshake[].attempts`, `tunnel.transport_bytes`, `session.prev`,
  `app.build`.
- **Автоотчёт реально отправляется** (раньше только собирался) и срабатывает на
  тихий обрыв живой сессии.
- **connect-event** на успешное подключение: `endpoint`, `endpoint_port`,
  `support_tag`, троттлинг 60 с (`frkn-docs/api-connect-event.md`).
- Одноразовый вопрос про диагностику после первого коннекта; телеметрия
  **выключена по умолчанию**.
- «Write to us»: сообщение + опционально отчёт, офлайн-очередь.
- «Диагностика»: `Check all servers`, отдельные **Send scan** / **Copy scan**,
  скан только при выключенном VPN, убран MTU, починен скролл.

## 8. UI

- Флаг страны берётся из страны ноды (отказ от `pool_country_code`, который
  приходил не туда).
- «Primary endpoint» убран из карточки; показывается адрес в работе.
- Тумблер **Experimental features** (по умолчанию выключен): без него нет
  сервисного сплит-туннеля; страница помечена «Experimental feature».
- Новый флаг `PIRATE`.
