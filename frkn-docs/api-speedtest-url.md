# ТЗ: `speedtest_url` — адрес бенча ноды в API

Статус: предложение. Репозитории: `ffcore` (api, node), потребители —
`status-page` и клиент `dopamine`.

---

## 1. Зачем

Замер скорости «с моего подключения до ноды» есть в двух местах:

1. **status.frkn.org** — по каждой ноде пула (`network.rs::measure_node_speed`);
2. **клиент Dopamine** — экран «Тест серверов» (`serverTestController.cpp`).

Оба строят адрес бенча **из имени ноды**:

```
<первая метка hostname>.bench.beacon.frkn.org:19443/speedtest/{1mb.test,10mb.test,ping.txt}
```

(например `eu01.frkn.org` → `eu01.bench.beacon.frkn.org`).

Этот контракт перестал существовать: записи в зоне переименованы в
`<provider>-<cc>-<city>-bench-01.bench.beacon.frkn.org`
(`mis-at-vie-bench-01`, `aeza-fr-par-bench-01`, `fbw-fr-par-bench-01`, …),
старые `<label>.bench` отдают NXDOMAIN.

Вывести новый адрес на стороне потребителя **невозможно**:

- по IP — PTR у провайдеров пустой или чужой (`177.177.20.172` → `b1b114ac.vie.customer.misaka.io`);
- по имени ноды — провайдер не выводится из `eu01`/`at`/`msk-tw`;
- перебором — клиент не может перечислить зону.

Итог: замер скорости по нодам сейчас не работает ни на странице, ни в приложении.
Правильное лечение — **отдавать адрес бенча из api**, чтобы потребителям не нужно
было ничего выводить.

## 2. Где отдавать

1. **`GET /status`** — публичный, для status.frkn.org. Поле рядом с `label`,
   `pool`, `ports`.
2. **`GET /v1/services`** — в объекте коннекшена, рядом с `node_ips`, `node_ports`.
3. **`GET /v1/config`** — рядом с `config` / `node_ips`.

Везде — одно и то же значение для одной ноды. Клиент уже читает
`displayInfo.speedtest_url` либо верхнеуровневый `speedtest_url` из конфига
строки; если поле отсутствует — падает на старую схему `<label>.bench`.

## 3. Формат

```jsonc
// GET /status
{
  "hostname": "at.frkn.org",
  "address": "177.177.20.172",
  "label": "AT AWG EU-09",
  "status": "Online",
  "ports": [6443, 8443, 51820],
  "pool": "EU Рилзопровод",
  "speedtest_url": "https://mis-at-vie-bench-01.bench.beacon.frkn.org:19443"
}
```

```jsonc
// GET /v1/services -> connections[]
{
  "connection_uuid": "1ac65b82-...",
  "node_id": "7f3c9a01-...",
  "node_ips": ["93.89.220.48"],
  "node_ports": { "93.89.220.48": 443 },
  "service_protocol": "AmneziaWg",
  "pool": "EU Рилзопровод",
  "speedtest_url": "https://soul-ee-tll-bench-01.bench.beacon.frkn.org:19443"
}
```

### Правила

- **Полный base URL**, а не только хост: `https://<host>:<port>`. Схема всегда
  `https`, порт всегда указывается явно (сейчас 19443).
- **Без завершающего слэша и без пути.** Клиент сам добавляет
  `/speedtest/1mb.test?cb=…`, `/speedtest/10mb.test?cb=…`, `/speedtest/ping.txt?cb=…`.
  Если хочется отдавать с путём — фиксируйте это в поле отдельным контрактом
  (`speedtest_path`), а не приклеиванием к URL.
- **Значение per node, не per address.** Бенч живёт на самой ноде, а не на
  каждом IP: `node_ips: 3` не даёт трёх адресов замера.
- **Значение per node, не per protocol.** Строки `amnezia-awg` и
  `amnezia-wg-mobile` одной ноды получают один и тот же URL.
- **Нет бенча → `null` (поле присутствует всегда** и в `/status`, и в
  коннекшене). Это нормальное состояние: у премиум-слотов бенча нет.
  Потребитель обязан показать «нет тест-файла», а не «0 Мбит/с».
- **Не проксировать.** URL должен вести на саму ноду. Центральный прокси
  измерит свой канал и выдаст одно число на все ноды.

## 4. Источник истины

Значение живёт там же, где живёт бенч — в конфиге ноды (fnode), например:

```toml
[node]
pool = "eu"
bench_url = "https://ncr-nl-ams-bench-01.bench.beacon.frkn.org:19443"
```

api отдаёт его **дословно**, ничего не достраивая. Если поле в конфиге не задано —
`null` (никаких «угадать по hostname», иначе снова появятся два источника истины).

Допустимая альтернатива, если правка fnode нежелательна: реестр нод в api
(`nodes.bench_url`), обновляемый вместе с остальными метриками heartbeat.
Хранить в двух местах нельзя.

## 5. Валидация на стороне api

При записи/обновлении значения:

1. схема `https`, хост оканчивается на `.bench.beacon.frkn.org` (сертификат
   `*.bench.beacon.frkn.org` — единственный, который валиден на этих нодах);
2. порт указан и непустой;
3. `GET <url>/speedtest/ping.txt` отвечает `200` (короткий таймаут, при провале —
   значение считается `null` и в ответ не попадает: пусть лучше поле пустое,
   чем клиент будет ждать таймаут на каждой ноде).

Проверка не должна блокировать ответ: значение кэшируется, проверяется на
heartbeat, а `/status` отдаёт последнее известное.

## 6. Обратная совместимость

- Поле **новое и опциональное**: старые клиенты и текущая страница его просто
  игнорируют, поведение не меняется.
- Новый клиент при отсутствии поля работает по старой схеме `<label>.bench…`
  (то есть сегодня — не работает, но и не падает).
- После выката api в прод страница и приложение перестают зависеть от имён в
  зоне: дальше бенч-хосты можно переименовывать сколько угодно.

## 7. Что НЕ входит в это ТЗ

- Замер через туннель (клиент меряет его сам, по файлу с той ноды, к которой
  подключён).
- Бенч на премиум-слотах — отдельная задача (там `speedtest_url` будет `null`,
  пока бенч не раскатан).
- Изменение размера файлов, порта и заголовков (`Access-Control-Allow-Origin: *`,
  `Cache-Control: no-store` уже обязательны для страницы).

## 8. Приёмка

```bash
# 1. /status отдаёт поле у всех пуловых нод
curl -s https://api.frkn.org/status | jq -r '.response[] | select(.pool) | "\(.hostname)\t\(.speedtest_url)"'

# 2. каждый адрес живой и отдаёт файл
curl -s https://api.frkn.org/status \
| jq -r '.response[] | select(.pool) | .speedtest_url' \
| while read -r u; do printf '%s ' "$u"; curl -s -o /dev/null -w '%{http_code} %{size_download}\n' "$u/speedtest/1mb.test"; done

# 3. /v1/services отдаёт то же значение (нужен ключ подписки)
curl -s -H "Authorization: Bearer <key>" https://api.frkn.org/v1/services \
| jq -r '.response.connections[] | "\(.connection_uuid)\t\(.speedtest_url)"'
```

Ожидаемо: 10 строк пула (3 пула), у каждой непустой `speedtest_url`, все отвечают
`200` и `1048576` байт. Дальше — приёмка потребителей: на status.frkn.org в блоке
«По пулам» снова появляются цифры по нодам; в клиенте на iPhone в «Тесте
серверов» заполняется колонка скорости.

## 9. Оценка

- node/config: поле + отдача в `/status` — 0.5 дня;
- api: `/v1/services` + `/v1/config` + валидация — 0.5 дня;
- релиз api + fnode на флот — по обычной процедуре (`frkn-server-releases`).

Потребителям (страница, клиент) правки **не нужны**: приоритет у поля, старая
схема остаётся фолбэком.
